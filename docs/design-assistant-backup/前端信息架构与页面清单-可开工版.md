# 「濮院毛衫」产业AI赋能平台：前端信息架构与页面清单（可开工版）

**版本**：V1.0  
**日期**：2026-05-18  
**适用阶段**：MVP（2026-05-20 ~ 2026-08-20）

---

## 1. 前端端型决策（已确认）

## 1.1 端型范围
- MVP上线端：**网站（Web）+ 微信小程序**。
- 暂缓端：**原生APP（iOS/Android）**，放入V1.0后评估。

## 1.2 原则
- 先验证商业闭环：注册 -> 充值 -> 调用插件 -> 扣费 -> 查账单。
- 先覆盖高频行为：商家日常操作在小程序，复杂配置与运营在Web。
- 尽量复用接口与业务逻辑：前后端分层，降低后续扩端成本。

---

## 2. 前端总体架构

## 2.1 MVP前端应用划分
- `merchant-web`：商家PC工作台（插件使用、账单、账户管理）。
- `admin-web`：平台管理后台（租户、插件、价格、账单、看板）。
- `merchant-miniapp`：商家微信小程序（轻操作与高频查看）。

## 2.2 技术选型建议（MVP）
- `merchant-web` / `admin-web`：Vue3 + TypeScript + Pinia + Vue Router + Element Plus。
- `merchant-miniapp`：Taro（React）或 uni-app（Vue）二选一。
- 建议本项目统一Vue生态：**uni-app（Vue3）优先**，便于团队复用。
- 网络层统一：Axios封装 + 统一拦截器（鉴权、错误码、重试）。

## 2.3 目录建议（示例）
```text
frontend/
  merchant-web/
  admin-web/
  merchant-miniapp/
  shared-sdk/
    api-client/
    types/
    utils/
```

## 6. 交互与组件规范（MVP）

## 6.1 统一交互规则
- 表单提交前端必校验；后端错误码二次提示。
- 长任务（图生成）使用异步任务态：`处理中/成功/失败`。
- 关键操作二次确认：禁用插件、冻结租户、手动扣费等。

## 6.2 共享组件（优先建设）
- 余额卡片组件 `BalanceCard`
- 插件卡片组件 `PluginCard`
- 流水表格组件 `LedgerTable`
- 任务状态组件 `TaskStatus`
- 错误提示组件 `ErrorNotice`

---

## 7. 前后端并行协作规则

- API先行：后端先出 OpenAPI 草案，前端基于 Mock 并行开发。
- 字段冻结：接口字段冻结后，仅允许向后兼容扩展。
- 联调节奏：每周三、周五固定联调窗口。
- 缺陷分级：`P0阻断` 当日修复，`P1` 48小时内修复。
