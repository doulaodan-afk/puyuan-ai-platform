**版本**：V1.0  
**日期**：2026-05-18  
**适用范围**：`merchant-web`、`admin-web`、`merchant-miniapp`

---

## 1. 角色定义

## 1.1 商家侧角色
- `merchant_owner`：老板，拥有租户内全部权限。
- `merchant_operator`：运营，可调用插件、查看账单、处理充值。
- `merchant_editor`：编辑，可调用插件，不可改价格与成员权限。
- `merchant_viewer`：只读，仅可查看结果与账单摘要。

## 1.2 平台侧角色
- `platform_super_admin`：超级管理员，平台全权限。
- `platform_ops`：运营，租户与插件运营权限。
- `platform_finance`：财务，对账、账单、充值审计权限。
- `platform_auditor`：审核员，审计与内容风控权限。

## 5. 前端权限中间件规则

## 5.1 路由守卫
- 未登录访问受保护路由，统一跳转登录页并记录 `redirect`。
- 登录后先拉取 `profile + role_code + tenant_status`，再进入路由。
- 租户状态为冻结时，除 `账单/联系客服` 页面外全部禁用。

## 5.2 按钮级权限（必须）
- 插件提交按钮：仅 `owner/operator/editor` 可见。
- 充值按钮：仅 `owner/operator` 可见。
- 调价按钮（管理端）：仅 `super_admin/finance` 可见，且强制二次确认。
- 冻结租户按钮：仅 `super_admin` 可见。

## 5.3 审计要求
- 高风险操作（调价、冻结、发布）必须写入审计日志。
- 前端提交写操作必须带 `X-Request-Id`，用于全链路追踪。

```ts
    requiresAuth: true,

  }

```

## 7. 联调检查单（路由与权限）

1. 未登录访问受保护路由，是否正确跳转。  
2. 不同角色登录后，菜单与按钮是否按权限展示。  
3. 越权操作是否返回统一错误码并前端提示。  
4. 冻结租户是否被限制高风险操作。  
5. 高风险操作是否在审计页可检索。
